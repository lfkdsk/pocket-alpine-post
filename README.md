# Alpine Post — 《山巅邮路》

A five-map, zero-combat mail-route RPG built on
[Pocket RPG Kit](https://github.com/lfkdsk/pocketjs-rpgkit) and
[PocketJS](https://github.com/pocket-stack/pocketjs). A relief postmaster
carries three letters up a rainy mountain before the last cable car stops:
the east-slope farm, the west-slope mine, the pine trail, and the
lighthouse at the top. The same bundle runs on the desktop host, the web
(wasm), and the PSP.

**In the browser:** <https://lfkdsk.github.io/pocket-alpine-post/> plays
the same bundle on the PocketJS core compiled to WebAssembly (Pocket RPG
Kit's `tools/web.ts`; `web.json` holds the card text and the key bindings).
The keys are the ones the in-game help lists, the mouse and touch walk and
talk as on the desktop, and saves are save codes: the browser has no
`data.fs`.

## The route

- **Mountain Hamlet** (24×15): the post office hands you the mailbag; the
  rainy-day chest pays 25 gold; the general store sells matches and hot
  soup.
- **East-Slope Farm** (22×14): feed the stuck herd three bales of hay,
  deliver the farmer's letter, and pick up two lost parcels.
- **West-Slope Mine** (16×12): the miner is fevered; hot soup gets his
  letter delivered. One more parcel.
- **Pine Trail** (18×12): a parcel, woodland mushrooms to sell, and the
  matches that repair the broken bridge.
- **Lighthouse Top** (16×14): the fifth parcel, the keeper's letter, three
  lamps to light, and the door to the lamp room. With all five parcels
  home the ending plays its five-parcel stanza.

**Attract mode.** After 10 seconds without input the game replays its
2,815-frame 60 Hz winning route from a clean world (`game/demo-tape.ts`,
generated by the deterministic driver in `game/journey.ts`). Demo text
reveals at 15 characters per second and completed dialog stays readable
for 1.5–2.5 virtual seconds. Any non-transport button takes control on the
current frame; **L** rewinds three virtual seconds; **SELECT** hands the
session back to the demo.

**Controls.** Arrow keys move and select; `Z` or Enter confirms; `X` or
Backspace cancels; `S` opens help (`A` too on the desktop); `Q` or `L` rewinds; Tab starts or
restarts the demo; Space opens the save menu. On the desktop and the web, click a
visible map tile to walk there or a dialog to advance; press a choice row
to highlight it and release to confirm. Hosts without the pointer channel
keep the full button controls.

## Build, test, run

```sh
git clone --recurse-submodules https://github.com/lfkdsk/pocket-alpine-post.git
cd pocket-alpine-post
bun run setup          # submodules (recursive) + bun install
bun run build:wasm     # one-time: the PocketJS wasm core for the sim tests
bun run build          # dist/alpine-post.js + .pak
bun test               # 91 tests: world, quests, journey, attract, pointer,
                       # save/load worldlines, pinned goldens
bunx tsc --noEmit
bun run desktop        # build for the desktop host and open a window
bun run package:macos  # on a Mac: dist/macos/Alpine Post.app + zip
bun run web            # the browser build in dist/web
```

`package:macos` wraps the desktop host, the bundle and the pak into a
double-clickable app with the lit lighthouse as its icon (Pocket RPG Kit's
`tools/package-macos.ts`). It is ad-hoc signed, not notarized: a
downloaded copy opens the first time with right-click > Open.

`bun run gen-assets` rebakes every map image, sprite, portrait, and atlas
from the Ninja Adventure sheets in `assets/src/ninja/` and the art scripts
in `art/`; the output is byte-identical to what is committed.
`bun art/preview.ts` renders each whole map with its characters, scaled
up, into `dist/preview/`, for reviewing art without booting the game.

Saves go to the per-app `data.fs` root, which on macOS is
`~/Library/Application Support/pocketjs/dev.lfkdsk.alpine-post/`. Web and
console builds use save codes instead.

## How it is put together

- `vendor/pocket-rpgkit` is a git submodule pinned to a Pocket RPG Kit
  commit. Its own `vendor/pocketjs` submodule pins PocketJS, so the kit
  alone decides the PocketJS version and the repository holds exactly one
  PocketJS.
- The game reads the kit only through its engine modules
  (`vendor/pocket-rpgkit/src/engine/*`: session, interpreter, save, attract,
  journey-search, and the rest). Imports are relative paths because
  PocketJS's build pass 1 follows relative imports.
- The game data lives in code (`game/game-data.ts`), and `gen-assets.ts`
  emits it as the `rpgkit-project/v1` document `data/alpine-post.json`.
  `game/restore.ts` adds cross-map loading on top of the kit's per-map
  restore gate. `ui/` holds the game's own screen, dialog (with speaker
  portraits), save menu, and HUD, and `input/pointer.ts` adds
  click-to-walk.
- The art is painted, not tiled: the maps are authored in logical tile
  ids that decide only where you can walk, and each map's art script
  (`art/maps.ts`) reads that layout and paints Ninja Adventure art over it
  — path and pond autotiles, trees and boulders as whole sprites, houses
  with roofs on the upper layer, a few pieces drawn in the pack's palette
  (`art/custom.ts`). Changing the art never changes the game.
- `tools/build.ts` builds the bundle into `dist/`. `tools/desktop.ts`
  resolves `pocket.json` against the desktop target, builds from that
  plan, and starts the PocketJS desktop host with this repository's
  artifacts. The sim tests boot the bundle by path on PocketJS's wasm sim
  host.

## Targets

| host | status |
| --- | --- |
| `macos-app` / `linux-app` (PocketJS desktop host) | primary; `data.fs` saves, pointer input |
| `web-app` (wasm) | same bundle; button controls, save codes |
| sim (wasm, headless) | the test suite: deterministic tapes, pinned frames |
| `psp` | admitted by `pocket check`; not run on hardware here |
